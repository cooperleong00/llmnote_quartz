# DAVINCI-LLM (2026)

DAVINCI-LLM 是一个来自 SII/SJTU/GAIR（Pengfei Liu 团队）的全开放预训练研究项目，占据了一个独特的生态位：将工业级计算资源与完全的学术研究自由结合。这篇论文的价值不在于模型本身（3B 参数），而在于它提供的系统性科学方法论——通过 200+ 控制消融实验，将预训练从"直觉驱动的手艺"推向"证据驱动的学科"。

核心贡献有三个支柱：(1) 采用 [[Data Darwinism]] 框架（L0-L9 分类体系）系统化数据处理决策；(2) 两阶段自适应课程训练，根据不同能力的饱和动态调整数据组成；(3) 200+ 控制消融实验揭示的经验性规律。最终 3B 模型在 8T tokens 训练后达到 51.72 overall average，匹配 OLMo-3 7B（51.65），MATH 上超出 23 分。

> - 标题：DAVINCI-LLM: Towards the Science of Pretraining
> - 作者：SII-GAIR (Pengfei Liu et al.)

## 动机

> [!intuition] 预训练研究的结构性悖论
> 预训练阶段决定了模型的能力天花板（post-training 难以弥补预训练阶段的能力缺陷），但这个阶段却严重缺乏科学研究。原因是一个结构性悖论：有算力的组织受商业压力限制透明度，有研究自由的学术机构缺乏预训练级别的算力。DAVINCI-LLM 试图填补这个交叉空白。

该项目的核心理念是"开放即方法论"——不仅开放最终产物，更开放完整的探索过程，包括失败的实验和决策逻辑，使社区能够在已有经验上积累科学知识。

## 贡献一：Data Darwinism 框架的应用

论文采用 [[Data Darwinism]] 框架，这是一个将数据处理操作组织为 10 级分类体系（L0-L9）的原则性框架，从基础过滤到内容合成：

| 层级 | 名称 | 核心操作 | 质变点 |
|------|------|----------|--------|
| L0 | Data Acquisition | 原始数据采集（web crawl、PDF、代码平台） | — |
| L1 | Format Normalization | 异构格式 → 统一文本（OCR、HTML 解析） | — |
| L2 | Rule-based Filtering | 确定性规则：去重、长度、语言、编码错误 | — |
| L3 | Lightweight Model Filtering | 语义级质量评估（教育价值、领域分类），纯选择 | — |
| L4 | Generative Refinement | **质变：选择 → 主动变换**。去噪、重组，保持语义等价 | 从"筛选"到"改写" |
| L5 | Cognitive Completion | 前沿 LLM 使隐式推理显式化（推理重建、术语阐释、教学桥接） | 从"保留"到"创造" |
| L6-L9 | Higher-Order Synthesis | 上下文补全、环境合成、生态合成、世界合成（理论层级） | — |

> [!warning] 关键细节
> 这些层级不是互斥的一次性操作。同一层级的操作可以用不同模型/prompt/参数多次应用，且操作顺序不必严格遵循层级——例如 L4 可以在 L3 之前执行。

### 处理深度的消融发现

论文在控制数据量和计算量的条件下，隔离了处理深度的因果效应：

- **L2 → L3**（模型过滤）：温和但一致的提升，MBPP +3.40，整体 +0.27
- **L3 → L4**（生成式精炼）：复杂推理上的显著提升，MATH +7.00。内容变换的价值超过体量扩展
- **L5**（认知补全）：通过领域对齐的 QA 合成实现定向能力引导。源-目标对齐强，但跨领域迁移有限

> [!intuition] 核心洞察
> 处理深度是与数据体量并列的系统性优化维度。分层数据处理可以替代数倍的数据量增长——这为数据受限场景提供了一条原则性替代路径。

## 贡献二：两阶段自适应课程训练

### 模型架构

基于 Qwen2 的 3B 参数 decoder-only transformer，从随机初始化训练：

| 参数 | 值 |
|------|-----|
| 参数量 | ~3.09B |
| 层数 | 36 |
| Hidden size | 2048 |
| Attention | GQA（16 query / 2 KV heads） |
| 激活函数 | SwiGLU（expansion ~5.4x） |
| 位置编码 | RoPE（base θ = 10000） |
| 序列长度 | 4096 |
| 词表 | 151936（Qwen2 tokenizer） |
| 精度 | bfloat16 |

### 训练阶段设计

总计 8T tokens，分为两大阶段四个子阶段：

```
Stage 1: General Foundation (6T)
├── Stage 1-1 (4T): 基础构建
│   CC 主导 (68.2%), 渐进 batch size (1024→2048→4096)
│   Constant LR 3e-4
│
└── Stage 1-2 (2T): 推理增强
    CC 降至 55.4%, Code +2.1%, Science +10.6%
    Cosine decay 3e-4 → 3e-5

Stage 2: Reasoning Enhancement (2T)
├── Stage 2-1 (1T): 平衡基础
│   30% QA + 30% Code + 30% Science + 10% Web
│   Constant LR 3e-5
│
└── Stage 2-2 (1T): QA 密集
    70% QA
    Constant LR 3e-5
```

> [!intuition] 为什么需要多子阶段？
> 不同能力有截然不同的饱和时间尺度：通用知识在 ~1T tokens 就趋于饱和，而代码和科学能力在 4T+ 仍持续增长。这种差异化饱和驱动了多子阶段设计——当某类能力饱和时，调整数据组成以继续推动其他能力增长。

### 训练动态

Stage 2 展现了高效的能力跃升：
- Stage 2-1 在仅 1T tokens 内将 overall average 从 39.58 推至 48.60
- MATH 从 Stage 1 的 22.0 跃升至最终的 62.8
- 这种效率源于更高处理深度的数据（L4/L5）的引入

这个两阶段课程本质上是一种 [[Mid-Training]] 策略——从通用基础逐步过渡到推理密集增强，与 mid-training 的"数据分布调整 + 学习率退火"范式高度一致。

## 贡献三：系统性消融发现

200+ 控制消融实验围绕四个主题展开：

### 1. 数据处理深度（Section 4.1）

见上文 Data Darwinism 消融。核心结论：处理深度是与体量缩放并列的关键维度。

### 2. 训练动态与自适应策略（Section 4.2）

- 不同能力有截然不同的饱和时间尺度
- 领域比例调整初期有效，但遇到递减收益
- 当标准语料格式集体趋近饱和时，重新分配比例不够——需要**格式转换**（原始文本 → 结构化 QA）
- 结构化 QA 显著优于持续的比例优化

> [!intuition] 格式转换的洞察
> 这是一个关键的认知跳跃：当所有原始文本格式的数据都接近饱和时，问题不在于"哪个领域的比例该增加"，而在于"数据的表现形式需要根本性改变"。从连续文本到 QA 对的格式转换，本质上改变了模型学习知识的方式。

### 3. 数据混合设计（Section 4.3）

- 代码与科学的内部平衡至关重要（C-30-S-30 > C-40-S-20）
- QA 浓度是阶段依赖的：Stage 2-1 保守（30%）保稳定，Stage 2-2 激进（70%）利用已建立的平衡基础
- 集中化与保持不是互斥的——自适应组合可以同时实现两者

### 4. 评估有效性（Section 4.4）

> [!warning] PPL vs 生成式评估的排名反转
> - PPL 评估衡量的是潜在知识访问（模型是否给正确答案更高概率）
> - 生成式评估衡量的是知识运用能力（模型能否主动产出答案）
> - 经过大量 QA 预训练的模型在生成式评估下获得不成比例的优势
> - 具体案例：OLMo-2-7B vs Qwen-2.5-3B 在 MMLU 上出现 3.10% 的摆动，导致排名反转
> - 两种协议都不是天然优越的——取决于部署场景

这个发现对预训练研究有深远影响：评估协议本身会塑造我们对模型质量的理解，选择不当可能导致错误的训练决策。

## 最终结果

3B 模型达到 51.72 overall average，匹配 OLMo-3 7B（51.65），参数量不到一半：

| 维度 | DAVINCI 3B | OLMo-3 7B | 差异 |
|------|-----------|-----------|------|
| Overall | 51.72 | 51.65 | +0.07 |
| MATH | **62.80** | 39.60 | **+23.20** |
| Avg Code | 55.99 | 54.42 | +1.57 |
| Avg Science | 48.30 | 45.98 | +2.32 |
| Avg General | 52.96 | 55.13 | -2.17（参数差距预期内） |

MATH 上 +23 分的巨大优势直接反映了 Stage 2 的 QA 密集训练和 L4/L5 数据处理的效果。

## 局限性

- **规模限制**：仅验证了 3B 规模，消融发现是否在更大规模上成立尚未验证
- **L5 跨领域迁移有限**：认知补全的 QA 合成展现强源-目标对齐，但跨领域迁移效果有限
- **评估偏差**：论文自身指出，评估协议选择会影响结论——其自身结果也受此影响
- **Data Darwinism L6-L9 未验证**：高阶合成层级仍为理论构想
- **英文为主**：训练数据和评估主要面向英文

## 对知识库的启示

> [!interview] 面试视角
> **Q: 预训练数据质量和数据量哪个更重要？**
> A: DAVINCI-LLM 的消融表明这是一个假二分法。处理深度是与体量并列的独立优化维度——L4 生成式精炼在 MATH 上带来 +7.00 的提升，这种质量增强可以替代数倍的数据量增长。但两者不是替代关系，而是互补维度。
>
> **Q: 为什么不同能力需要不同的训练策略？**
> A: 因为不同能力有不同的饱和动态。通用知识在 ~1T tokens 饱和，代码/科学在 4T+ 仍在增长。当某类能力饱和时，单纯调整比例不够，需要格式转换（文本 → QA）来突破瓶颈。
