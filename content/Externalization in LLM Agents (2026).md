# Externalization in LLM Agents (2026)

这篇综述提出一个很有解释力的视角：LLM 智能体（LLM agent）的可靠性越来越依赖外部认知基础设施。模型负责语言理解、综合推理和局部判断；记忆（memory）、技能（skills）、协议（protocols）与 harness 把长期状态、可复用流程、交互契约和运行治理放到模型外部，让模型面对的是更稳定、更可检查、更容易执行的任务。

如果 [[Agent Harness Engineering (2026)]] 关注 ETCLOVG 等 harness 工程层如何组成一个可执行系统，本文给出更上位的统一解释：这些工程层共同服务于 [[Cognitive Externalization|认知外化]]。[[Agent Harness for Large Language Model Agents (2026)]] 把 harness 分解成组件和挑战，本文则强调这些组件为什么会收敛到记忆、技能、协议与 harness 这组结构。

## 一句话定位

本文把 2022-2026 年 LLM 智能体的工程演化概括为从模型权重到上下文，再到 harness 的外移过程：能力先被理解为模型参数中的知识，随后被理解为提示词和上下文中的任务信息，进一步被理解为围绕模型运行的外部基础设施。这个视角的核心问题是：哪些认知负担适合继续留在模型内部，哪些应该转化成可持久、可复用、可验证、可治理的外部结构。

> [!intuition] 认知外化的直觉
> 人写购物清单时，记忆任务会从“凭脑子回忆所有物品”转为“看见清单并识别是否齐全”。LLM 智能体中的外化也在做类似的代表性转换：记忆把回忆转成检索，技能把临场发明流程转成加载和组合，协议把自由文本协调转成结构化交换，harness 把这些结构编排成可运行的行动环境。

## 为什么需要这个框架

裸模型在智能体场景里会遇到三类反复出现的错配。

第一，长时程任务要求持续状态，而上下文窗口会截断、稀释或遗失历史。[[RAG]] 可以把外部语义知识带回当前推理，智能体记忆进一步把任务状态、执行轨迹、用户偏好和项目事实纳入可读写的外部状态。

第二，多步任务要求稳定流程，而模型经常在每次调用时重新组织步骤。[[Chain-of-Thought]] 让中间推理显式进入上下文，技能则把反复有效的工作流、决策启发和约束沉淀成可发现、可加载、可组合的外部产物。

第三，真实行动要求可治理的接口，而自由文本提示很难稳定承担工具调用、子代理委托、权限检查、状态流转和失败恢复。[[MCP]]、[[A2A]] 这类协议把能力发现、参数结构、生命周期事件和信任边界写成机器可读的契约，使智能体的输出从普通文本变成可验证的行动提案。

本文的价值在于把这些方向放到同一个解释框架里：记忆、技能和协议分别外化状态、程序性专长和交互结构；harness 把三者放进带有权限、控制、可观测性和反馈循环的运行环境。

## 四层外化框架

### 1. 记忆外化状态

记忆处理的是时间负担。一个智能体要跨会话、跨分支、跨中断地工作，就需要把“现在任务做到哪里”“过去哪些路径成功或失败”“用户和环境有哪些稳定偏好”保存到模型外部。

论文把记忆内容分成四类：

- 工作上下文（working context）：当前任务的活跃状态，例如打开文件、临时变量、部分计划、执行 checkpoint。
- 情节经验（episodic experience）：过去运行中的决策点、工具调用、失败原因、结果和反思。
- 语义知识（semantic knowledge）：跨案例稳定成立的知识，例如领域事实、项目约定、通用启发。
- 个性化记忆（personalized memory）：特定用户、团队或环境的偏好、约束和长期交互记录。

这些内容的工程趋势从单一长上下文，走向检索存储、层级记忆、冷热分层、抽取与遗忘策略，再走向自适应检索和路由。这里的关键变化是从“存更多”走向“控制什么该写入、提升、检索、压缩和遗忘”。在成熟 harness 中，记忆成为控制面的一部分，决定模型在每一步能基于怎样的过去行动。

### 2. 技能外化程序性专长

技能处理的是流程负担。工具只暴露操作，协议规定操作如何被调用，技能则编码一类任务应该如何完成。一个可用技能通常包含三部分：

- 操作流程（operational procedure）：任务拆解、阶段顺序、依赖关系、停止条件。
- 决策启发（decision heuristics）：遇到分支时优先尝试什么、何时退回、何时升级、什么证据足够。
- 规范约束（normative constraints）：测试要求、权限边界、合规规则、可追溯性和安全条件。

这解释了为什么技能文件、AGENTS.md、SOP、项目级指令和组织级流程文档会在智能体系统里变得重要。它们把原本需要模型每次重新生成的做事方法，变成可检查、可修订、可复用的外部对象。

技能系统的成熟度取决于五个运行环节：规格说明（specification）描述能力和边界，发现（discovery）找到相关技能，渐进披露（progressive disclosure）按需加载细节，执行绑定（execution binding）绑定工具、文件、API 或子代理，组合（composition）把多个技能组合成更高层能力。这个视角也解释了 [[SWE-Bench]] 这类代码任务中项目惯例、测试流程和修复步骤为什么适合沉淀为技能：它们主要降低程序性方差；单次语言生成难度只是其中一小部分。

### 3. 协议外化交互结构

协议处理的是交互负担。智能体调工具、委托子代理、向用户展示状态或执行支付等高风险流程时，需要稳定回答四个问题：

- 调用语法（invocation grammar）：调用字段、类型、返回结构是什么。
- 生命周期语义（lifecycle semantics）：任务处于哪个阶段，谁行动，何时完成，何时失败。
- 权限与信任边界（permission and trust boundaries）：谁有权做什么，数据可以流向哪里，哪些操作需要审批。
- 发现元数据（discovery metadata）：有哪些能力可用，如何找到它们，版本和约束是什么。

协议把这些信息从提示词和临场推断中抽出，放进结构化契约。MCP 代表智能体到工具协议，A2A 代表智能体到智能体协议，A2UI 和 AG-UI 代表智能体到用户的交互表面，UCP 与 AP2 则说明垂直领域协议可以把购物、支付、授权和审计对象纳入同一套可执行流程。

协议的认知作用很直接：模型仍然判断要不要行动、选择哪个行动路径；协议承担格式、校验、状态转移和权限边界。这样，错误类别也更可诊断：参数格式错属于行动结构定义问题，委托状态错属于生命周期问题，权限越界属于信任边界问题。

### 4. Harness 统一外化模块

Harness 是承载记忆、技能和协议的运行环境。它包含智能体循环、沙箱、审批门、可观测性、配置、权限、策略编码和上下文预算管理。它决定模型看到什么、能访问什么、如何行动、哪些行动需要审批、失败如何记录、反馈如何进入下一轮改进。

这个定义和 [[Agent Harness Engineering (2026)]] 的工程视角可以互补阅读：ETCLOVG 更适合做系统拆解清单，本文的外化框架更适合解释这些清单背后的认知功能。两篇论文都指向同一个实践判断：长程智能体的可靠性来自模型与运行环境的耦合质量。

## 模块之间如何互相塑造

论文最有用的部分之一，是把记忆、技能、协议的关系画成一个循环。

记忆到技能：执行轨迹和失败案例可以被抽取成可复用流程。经验蒸馏做得太激进，会把偶然有效的路径固化为误导性技能；做得太保守，又会浪费已经获得的经验。

技能到记忆：每次技能执行都会产生轨迹、失败点、参数选择和用户反馈。可观测性把这些记录写回记忆，让技能维护有证据基础。

技能到协议：技能只说明高层流程，具体行动要通过协议化接口执行。协议层可以拦截参数错误、权限越界和危险组合。

协议到技能：稳定接口会催生围绕接口的最佳实践。一个可发现、可调用、可审计的协议表面，往往会成为一组新技能的生成土壤。

记忆到协议：历史成功率、用户偏好和工具失败记录会影响路由决策。例如同一个任务可以本地执行、经 MCP 调工具，或通过 A2A 委托给远端智能体。

协议到记忆：工具结果、审批事件、错误载荷和委托结果需要被规范化写回记忆。后续推理会基于这些外部状态继续行动，所以写回格式和可信度标记非常重要。

这些耦合让 harness 成为必要的协调层。三个模块共享同一个上下文预算，运行在不同时间尺度上，也会互相放大错误。一次记忆污染可能诱导错误技能，错误技能又会生成污染后的新轨迹。只有 harness 级别的审计、回滚、权限和评估，才能切断这种级联。

## 如何判断该外化什么

外化需要边际收益约束。本文给出的判断维度很实用：

- 更新频率高、衰减快的知识和流程适合外化，例如 API、组织政策、项目状态、用户偏好。
- 需要跨任务、跨用户、跨智能体复用的能力适合外化，例如代码修复流程、数据分析报告流程、调试 SOP。
- 需要审计、审批、回滚和策略执行的行为适合外化，例如支付、生产环境修改、敏感数据访问。
- 低延迟、低方差、纯语义、稳定通用的能力适合留在模型参数中，例如常识推理、语言理解、常见代码模式识别。

> [!warning] 外化的边界
> 外化会引入额外成本：检索、路由、解析、权限检查和工具调用都会增加延迟；记忆、技能、协议结构定义会竞争上下文窗口；过多外部产物会让模型把精力花在发现和协调模块上。好的 harness 追求最小充分外化：每个外部模块都应该减少模型的认知负担，并且带来可测的可靠性、可维护性或治理收益。

## 风险与治理

外部结构带来可检查性，也扩大了攻击面。记忆污染可以污染未来推理，恶意技能注入可以把对抗流程写进可复用能力库，协议伪造可以伪造工具 manifest 或 endpoint，让智能体在合法表象下执行未授权动作。

因此，治理本身也要作为 harness 基础设施来设计：关键记忆和技能更新需要来源记录，危险操作需要审批门，高风险协议调用需要结构定义校验和权限检查，失败后需要回滚与回归测试。随着 [[Self-Evolving Harness|自演化 harness]] 出现，治理的重要性会进一步上升，因为系统开始调整自己的检索粒度、技能排序、协议路由、执行顺序和资源分配。

## 速查

> [!example] 四个代表性转换
> - 记忆：回忆 -> 检索，把跨时间状态变成可检索对象。
> - 技能：临场生成 -> 指导式组合，把临场流程生成变成可加载、可组合的程序性指导。
> - 协议：临场协调 -> 结构化交换，把自由文本协调变成机器可读契约。
> - Harness：模型调用 -> 受治理运行时，把单次调用变成带权限、控制、可观测性和反馈循环的执行环境。

> [!interview] 面试视角
> **Q: 这篇论文里的外化和普通工具调用有什么区别？**
> A: 工具调用只解决“模型如何触达外部操作”的一小部分问题。外化是更大的系统视角：记忆保存状态，技能保存程序性专长，协议规定交互契约，harness 负责权限、控制、观测和反馈。它解释的是可靠智能体能力如何从模型与外部基础设施的耦合中出现。

> [!interview] 面试视角
> **Q: 为什么 harness 是统一层？**
> A: 记忆、技能和协议会共享上下文预算、互相产生输入、运行在不同时间尺度上，也会互相传播错误。Harness 负责调度和治理这些耦合：选择检索什么、加载哪个技能、走哪条协议路径、何时请求审批、如何记录失败、如何把结果写回系统。
