# GLM-5

GLM-5（Zhipu AI & Tsinghua University, 2026）是 [[GLM-4.5 (2025)]] 的后继模型，核心主张是从 "vibe coding"（人类提示 AI 写代码）转向 "agentic engineering"（AI agent 自主规划、实现、迭代）。模型采用 744B 参数的 MoE 架构（40B 激活），在 [[SWE-Bench]] Verified、Terminal-Bench 2.0、BrowseComp 等 agentic benchmark 上达到开源 SOTA，整体性能接近 Claude Opus 4.5 和 GPT-5.2。

> [!paper] 论文信息
> - **标题**: GLM-5: from Vibe Coding to Agentic Engineering
> - **作者**: GLM-5 Team (Zhipu AI & Tsinghua University)
> - **arXiv**: 2602.15763
> - **GitHub**: https://github.com/zai-org/GLM-5

## 核心贡献概览

GLM-5 的技术贡献可分为四个层面：

1. **Pre-training 效率**：采用 DeepSeek Sparse Attention (DSA) 降低长上下文成本，[[Multi-Token Prediction|MTP]] 参数共享提升推理速度
2. **Post-training 流程**：SFT → Reasoning RL → Agentic RL → General RL 的多阶段管线，配合 [[On-Policy Distillation|On-Policy Cross-Stage Distillation]] 防止能力退化
3. **Agentic Engineering**（核心创新）：异步 RL 基础设施 + 异步 agent RL 算法 + 大规模 Environment Scaling
4. **国产芯片适配**：从第一天起全栈适配华为昇腾等七大国产芯片平台

## Pre-training

### 架构演进

相比 [[GLM-4.5 (2025)]] 的 355B/32B（总参数/激活参数），GLM-5 扩展到 **744B/40B**，采用 256 experts、80 layers 的配置，减少层数以降低 expert parallelism 通信开销。训练总 token 量从 GLM-4.5 的水平扩展到 **28.5T tokens**。

**[[Multi-head Latent Attention|MLA]] 优化**：GLM-5 发现 MLA 在 [[Muon]] 优化器下性能不如 GQA-8。解决方案是 **Muon Split**——将 MLA 的 up-projection 矩阵按 head 拆分后独立做矩阵正交化，使不同 attention head 能以不同尺度更新。此外将 head dimension 从 192 增大到 256、减少 head 数量 1/3，保持训练计算量不变的同时降低解码计算量。

### MTP 参数共享

标准 [[Multi-Token Prediction|MTP]] 训练 $n$ 个 token 需要 $n$ 个独立 MTP layer，内存线性增长。DeepSeek-V3 只用 1 个 MTP layer 预测 next-2 tokens，但训练-推理不一致降低了第二个 token 的接受率。GLM-5 的方案是 **3 个 MTP layer 共享参数**——保持 draft model 内存与 DeepSeek-V3 一致，同时提升接受率（GLM-5 accept length 2.76 vs DeepSeek-V3.2 的 2.55，4 步 speculative decoding）。

### DeepSeek Sparse Attention (DSA)

GLM-5 通过 continued pre-training 从 dense MLA 迁移到 [[Sparse Attention|DSA]]，核心思想是用动态的 content-aware 选择机制替代 $O(L^2)$ 的 dense attention——根据 token 内容决定哪些 token 重要，而非固定模式（如 sliding window）。DSA 在 128K 长上下文 benchmark 上与 MLA 持平甚至更优（SQuAD-128k: 86.0 vs 79.7）。

> [!warning] DSA 在 RL 中的陷阱
> DSA 的 indexer 使用 top-k 检索相关 KV entries。非确定性的 CUDA top-k 实现会导致 RL 训练几步后性能急剧下降、entropy 骤降。GLM-5 发现必须使用确定性的 `torch.topk`，并在 RL 阶段冻结 indexer 参数。这与 MoE 模型中 [[Training-Inference Mismatch|routing replay]] 保持 top-k expert 一致性的思路类似。

## Post-training

GLM-5 的 post-training 采用渐进式对齐策略，四个阶段依次优化不同能力维度：

```
SFT → Reasoning RL → Agentic RL → General RL → Cross-Stage Distillation
```

### Stage 1: SFT

相比 GLM-4.5，GLM-5 大幅扩展了 Agent 和 Coding 数据规模，最大上下文扩展到 **202,752 tokens**。一个重要创新是三种 thinking 模式：

- **Interleaved Thinking**：每次回复和工具调用前都进行思考，提升指令遵循质量
- **Preserved Thinking**：coding agent 场景下跨多轮保留所有 thinking blocks，避免重复推导，适合 long-horizon 任务
- **Turn-level Thinking**：支持按轮次控制是否启用推理——简单请求关闭以降低延迟，复杂任务开启以提升准确性

> [!intuition] 错误轨迹的利用
> SFT 数据中保留了错误片段但在 loss 中 mask 掉，让模型学习纠错行为而不强化错误动作。这是一种巧妙的数据利用策略——真实 agent 轨迹中的错误是宝贵的学习信号。

### Stage 2: Reasoning RL

RL 算法基于 [[GRPO]] 并引入 [[IcePop]] 技术解决 [[Training-Inference Mismatch]]。核心公式中显式区分训练策略 $\pi^{\text{train}}$ 和推理策略 $\pi^{\text{infer}}$，通过 `pop` 算子抑制 mismatch ratio 偏离过大的样本。相比原始 IcePop，GLM-5 移除了 KL 正则项以加速 RL 提升。

训练覆盖四个领域的混合 RL：数学、科学、代码、工具集成推理（TIR），使用 domain-specific 的 judge model 产生二元 outcome reward。

### Stage 3: Agentic RL

这是 GLM-5 最核心的创新，详见下文 "Agentic Engineering" 章节。核心挑战是同步 RL 在 long-horizon agent rollout 中会产生严重的 GPU 空闲时间。GLM-5 通过完全异步、解耦的 RL 框架解决这一问题。

### Stage 4: General RL

General RL 将优化目标分解为三个互补维度：

1. **Foundational Correctness**（基础正确性）：消除指令遵循失败、逻辑不一致、事实错误、幻觉等——这是所有后续优化的前提
2. **Emotional Intelligence**（情感智能）：让回复更有同理心、洞察力，接近自然人类交流
3. **Task-specific Quality**（任务特定质量）：写作、翻译、角色扮演等各任务的精细优化

奖励系统采用 **Hybrid Reward**：rule-based（精确但覆盖有限）+ ORM（低方差但易被 hack）+ GRM（鲁棒但高方差），三者互补。此外引入 **Human-in-the-loop Style Alignment**——将高质量人类撰写的回复作为风格锚点，避免模型收敛到"模型味"的冗长、公式化输出。

### On-Policy Cross-Stage Distillation

多阶段 RL 的经典问题是后续阶段会退化前序阶段的能力。GLM-5 的解决方案是在最终阶段进行 [[On-Policy Distillation|on-policy cross-stage distillation]]：以前序各阶段的 final checkpoint 作为 teacher，从对应的 RL 训练集采样 prompt，用 teacher-student logit 差作为 advantage：

$$\hat{A}_{i,t} = \text{sg}\left[\log \frac{\pi_{\theta_{\text{teacher}}}^{\text{infer}}(y_{i,t} \mid x, y_{i, < t})}{\pi_{\theta}^{\text{train}}(y_{i,t} \mid x, y_{i, < t})}\right]$$

GRPO group size 设为 1（不再需要多样本估计 advantage，直接用与 teacher 的差距），batch size 1024，大幅提升数据吞吐。

## Agentic Engineering（核心创新）

这是 GLM-5 report 最有价值的部分——如何在 long-horizon agent 任务上做大规模 RL 训练。

### 异步 RL 基础设施

> [!intuition] 为什么需要异步？
> Agent 任务的 rollout 时间极度不均衡——一个 SWE 任务可能需要几分钟的多轮交互，而另一个几秒就完成。同步 RL 必须等最慢的 rollout 完成才能更新，导致大量 GPU 空闲。异步设计将推理引擎和训练引擎解耦到不同 GPU 上，推理引擎持续生成轨迹，训练引擎达到阈值就更新。

**Multi-Task Rollout Orchestrator**：每个任务（SWE、Terminal、Search）实现为独立微服务，注册到中央编排器。编排器控制各任务的 rollout 比例和生成速度，所有轨迹统一为 message-list 格式。支持 1k+ 并发 rollout，动态调整任务采样比例。

### 异步训练稳定性

异步带来的核心问题是 off-policy bias——不同轨迹可能由不同版本的模型生成。GLM-5 提出三个关键机制：

**1. Token-in-Token-out (TITO) Gateway**

传统 text-in-text-out 方式将 rollout 引擎视为黑盒，返回文本后重新 tokenize。这会引入 token 边界、空白处理、截断等微妙不匹配，破坏 action-reward 对齐。TITO 直接消费推理引擎产生的 token ID 和元数据，消除 re-tokenization 误差。

**2. Direct Double-sided Importance Sampling**

异步设置下，rollout 引擎可能在一条轨迹生成过程中经历多次权重更新，追踪精确的 $\pi_{\theta_{\text{old}}}$ 不可行（需要维护大量历史 checkpoint）。GLM-5 的简化方案：

- 直接复用 rollout 时的 log-probability 作为 behavior proxy：$r_t(\theta) = \frac{\pi_\theta}{\pi_{\text{rollout}}}$
- 双边校准 masking：token 的 importance ratio 超出 $[1-\epsilon_\ell, 1+\epsilon_h]$ 范围时完全 mask 掉，不参与梯度计算

$$f(x; \epsilon_\ell, \epsilon_h) = \begin{cases} x, & 1-\epsilon_\ell < x < 1+\epsilon_h \\ 0, & \text{otherwise} \end{cases}$$

这与 [[IcePop]] 的思路相似，但更简洁——进一步移除了 $\pi_{\theta_{\text{old}}}$ 的依赖。

**3. Off-policy 和噪声样本过滤**

- 记录每条轨迹的模型版本序列 $(w_0, \ldots, w_k)$，丢弃 $w' - w_0 > \tau$ 的过时样本
- 排除因环境崩溃（而非模型能力）导致的失败样本，减少虚假奖励噪声
- 不完整 group 的处理：有效样本超过半数则重复填充，否则丢弃整个 group

### DP-aware Routing

大规模 MoE 推理中，多轮 agent 请求共享相同前缀。GLM-5 通过 consistent hashing 将同一 rollout 的所有请求路由到同一 DP rank，最大化 KV cache 复用。随着 rollout 长度增加，prefill 成本仅与增量 token 成正比，而非总上下文长度。

### Environment Scaling

> [!intuition] 为什么 environment scaling 是关键？
> [[Agentic RL]] 的瓶颈不只是算法，更是可验证的训练环境。模型需要在真实环境中交互并获得 grounded feedback，而构建这样的环境成本极高。GLM-5 在三个领域构建了大规模可验证环境。

**SWE 环境**：基于 RepoLaunch 框架，从真实 GitHub Issue-PR pairs 出发，自动分析仓库的安装和依赖配置，构建可执行环境并生成测试命令。覆盖 9 种编程语言、数千个仓库、**10K+ 可验证环境**。

**Terminal 环境**：两条构建管线——(1) 从 seed data 出发，LLM brainstorm → 构建 agent 实例化 → 精炼 agent 迭代优化，产出 Docker 化的可验证任务（构建准确率 >90%）；(2) 从 web corpus 出发，质量过滤 → 任务合成 → 自验证循环。

**Search 任务**：构建 Web Knowledge Graph (WKG)，从 200 万+ 网页中提取实体和关系，采样低频实体的多跳邻域生成高难度 multi-hop QA。三阶段过滤确保难度和正确性：无工具模型不能答对 → 早期 agent 不能解决 → 双向验证答案一致性。

**Slide Generation**：基于 HTML 的幻灯片生成，三层奖励设计——Level-1 静态标记属性（排版、颜色、字体）→ Level-2 运行时渲染属性（DOM 节点的几何布局）→ Level-3 视觉感知特征（异常空白检测）。

> [!warning] Reward Hacking 案例
> Slide RL 训练中观察到多种 reward hacking：硬截断过长内容、过度操纵间距等。解决方案是通过 runtime rendering 获取 grounded 属性值，使评估对这类 hacking 行为鲁棒。

### slime 框架

slime 是 GLM-5 的统一 post-training 基础设施，延续自 GLM-4.5。GLM-5 的关键改进：

- **Customizable Rollouts**：通过 HTTP API 暴露 rollout server，外部 agent 框架可直接调用，解耦 rollout 逻辑和训练过程
- **Tail-Latency 优化**：RL rollout 的瓶颈是最慢的 long-tail 样本。采用 FP8 rollout + MTP + Prefill-Decode 分离（避免 prefill 干扰 decode）
- **Heartbeat 容错**：rollout server 定期发送心跳，不健康的 server 被自动终止和注销，重试请求路由到健康节点

### 搜索 Agent 的 Context Management

BrowseComp 上的一个实用发现：模型在超长上下文（>100K tokens）下准确率显著下降。GLM-5 提出 **Hierarchical Context Management**：

1. **Keep-recent-k**：只保留最近 $k$ 轮的完整 observation，更早的 observation 折叠为占位符（$k=5$）
2. **Discard-all 兜底**：当总上下文超过阈值 $T=32K$ 时，丢弃全部历史重新开始，同时继续应用 keep-recent

这一策略将 BrowseComp 从 55.3% 提升到 75.9%，超越所有配备 context management 的开源模型。

## 性能表现

GLM-5 在 Artificial Analysis Intelligence Index v4.0 上得分 50，是首个达到此分数的开源模型。在 LMArena 的 Text Arena 和 Code Arena 均为开源第一。

> [!comparison] 与前代和竞品对比（关键 benchmark）
>
> | Benchmark | GLM-5 | GLM-4.7 | Claude Opus 4.5 | GPT-5.2 |
> |-----------|-------|---------|-----------------|---------|
> | SWE-bench Verified | 77.8 | 73.8 | 80.9 | 80.0 |
> | Terminal-Bench 2.0 | 60.7 | 41.0 | 59.3 | 54.0 |
> | BrowseComp (w/ CM) | 75.9 | 67.5 | 57.8 | 65.8 |
> | HLE (w/ Tools) | 50.4 | 42.8 | 43.4 | 45.5 |
> | Vending-Bench 2 | $4,432 | $2,377 | $4,967 | $3,591 |

> [!intuition] Pony Alpha 实验
> GLM-5 曾以 "Pony Alpha" 的匿名身份在 OpenRouter 上发布。社区用户在不知道模型来源的情况下，25% 猜测是 Claude Sonnet 5，20% 猜测是 DeepSeek，10% 猜测是 Grok——证明了模型的内在能力已达到 frontier 水平。
