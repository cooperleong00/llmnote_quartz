# VAPO (2025)

VAPO（Value-model-based Augmented Proximal Policy Optimization）是 ByteDance Seed 提出的 RL 训练框架，专门针对 reasoning model 的 long-CoT 任务。核心论点是：如果能解决 value model 训练中的固有挑战，value-model-based 方法的性能上限高于 [[GRPO]]、[[DAPO]] 等 value-model-free 方法。基于 Qwen2.5-32B，VAPO 在 AIME 2024 上达到 60.4 分，超越 DAPO（50 分）和 DeepSeek-R1-Zero-Qwen-32B（47 分）10+ 分。

> [!paper] 论文信息
> - **标题**: VAPO: Efficient and Reliable Reinforcement Learning for Advanced Reasoning Tasks
> - **机构**: ByteDance Seed
> - **日期**: 2025-04-14
> - **ArXiv**: 2504.05118v3

## 动机：为什么坚持 Value Model

在 LLM RL 训练中，[[GRPO]] 和 [[DAPO]] 等 value-model-free 方法已经取得了显著成功——它们不需要训练 value model，直接用 trajectory-level reward 的 group 统计量作为 advantage。这种方法简单、稳定，因此成为主流。

但 VAPO 的核心论点是：value-model-free 方法存在**性能天花板**。原因有三：

1. **Credit assignment 粒度不足**：value-model-free 方法将整条 trajectory 的 reward 均匀分配给每个 token，无法区分"哪一步推理是关键的"。对于复杂推理任务，一步微小的错误可能导致整个推理链失败，粗粒度的 credit assignment 难以精确定位问题。

2. **Variance 较高**：Monte Carlo 估计的 advantage 天然具有高方差，尤其在 long-CoT 场景下，trajectory 长度可达数千 token，方差问题更加严重。

3. **样本利用效率低**：没有 value model 的泛化能力，每个样本的信息只能通过 group 内的相对比较来利用。

Value model 能提供 token-level 的精细信号，理论上可以实现更好的 credit assignment 和更低的 variance。问题在于：**在 long-CoT 场景下训练一个可靠的 value model 非常困难**。VAPO 的贡献就是系统性地解决这些困难。

## 三大挑战与解决方案

VAPO 识别了 value-model-based 方法在 long-CoT 任务中面临的三个核心挑战，并为每个挑战提出了针对性的解决方案。

### 挑战一：Value Model Bias

**问题**：Value model 通常从 [[Reward Model]] 初始化，但两者的目标不同——reward model 只在 `<EOS>` token 上打分，而 value model 需要估计每个 token 位置的期望累积回报。这种目标不匹配导致严重的初始化偏差。再加上 [[GAE]] 的 bootstrapping 机制，偏差会沿 trajectory 累积，在长序列上尤为严重。

**解决方案**：

**Value-Pretraining**（来自 [[VC-PPO]]）：在正式 RL 训练前，先用固定策略采样 response，用 Monte Carlo return 预训练 value model，直到 value loss 和 explained variance 达到合理水平。这一步消除了 reward model 初始化带来的偏差。

> [!warning] 关键性
> 消融实验显示，去掉 Value-Pretraining 后模型直接崩溃（60 → 11 分），与 vanilla PPO 的表现一致。这是 VAPO 中**最关键**的组件。

**Decoupled-GAE**（来自 [[VC-PPO]]）：将 value 更新和 policy 更新的 [[GAE]] 计算解耦——value 更新使用 $\lambda_{\text{critic}} = 1.0$（无偏的 Monte Carlo return），policy 更新使用较小的 $\lambda_{\text{policy}}$（加速收敛）。这样 value model 的学习目标是无偏的，不会因为 bootstrapping 而累积误差。

### 挑战二：Heterogeneous Sequence Lengths

**问题**：复杂推理任务中，模型生成的 response 长度差异极大（从几十到几千 token）。标准 [[GAE]] 使用固定的 $\lambda = 0.95$，但对于长度 $l > 100$ 的序列，reward 信号的衰减系数 $0.95^{100} \approx 0.006$，几乎为零。这意味着长序列的 GAE 完全由 bootstrapping 主导，而短序列则方差过高。固定 $\lambda$ 无法同时适应两种情况。

**解决方案——Length-Adaptive GAE**（VAPO 的核心创新）：

> [!intuition] 直觉
> 不同长度的序列需要不同的 bias-variance 权衡。短序列需要更多 bootstrapping（降低方差），长序列需要更多 Monte Carlo 信号（降低偏差）。Length-adaptive GAE 让 $\lambda$ 随序列长度自适应调整。

设计思路是让 TD-error 系数之和与序列长度 $l$ 成正比：

$$\sum_{t=0}^{\infty} \lambda_{\text{policy}}^t \approx \frac{1}{1 - \lambda_{\text{policy}}} = \alpha l$$

解出：

$$\lambda_{\text{policy}} = 1 - \frac{1}{\alpha l}$$

其中 $\alpha$ 是控制整体 bias-variance 权衡的超参数（VAPO 中取 $\alpha = 0.05$）。

这个公式的效果是：
- **短序列**（$l$ 小）→ $\lambda$ 较小 → 更多 bootstrapping → 降低方差
- **长序列**（$l$ 大）→ $\lambda$ 接近 1 → 更多 Monte Carlo 信号 → 降低偏差

> [!math] 数值示例
> - $l = 20$: $\lambda = 1 - 1/(0.05 \times 20) = 0$（纯 TD）
> - $l = 100$: $\lambda = 1 - 1/5 = 0.8$
> - $l = 1000$: $\lambda = 1 - 1/50 = 0.98$（接近 Monte Carlo）

**Token-Level Policy Gradient Loss**（来自 [[DAPO]]）：标准 PPO loss 先在序列内平均、再在 batch 内平均，导致长序列中每个 token 的贡献被稀释。Token-level loss 改为在整个 batch 的所有 token 上均匀加权：

$$\mathcal{L}_{\text{PPO}}(\theta) = -\frac{1}{\sum_{i=1}^{G} |o_i|} \sum_{i=1}^{G} \sum_{t=1}^{|o_i|} \min\left(r_{i,t}(\theta) \hat{A}_{i,t},\ \text{clip}\left(r_{i,t}(\theta), 1 - \varepsilon, 1 + \varepsilon\right) \hat{A}_{i,t}\right)$$

这让长序列中的问题能被充分抑制，避免训练不稳定。

### 挑战三：Reward Signal Sparsity

**问题**：Verifier-based 任务（如数学推理）只提供 binary reward（0/1），不像传统 reward model 那样给出连续分数。Long-CoT 进一步加剧了稀疏性——生成时间更长，正确答案更稀少。模型面临严峻的 exploration-exploitation 困境。

**解决方案**：

**Clip-Higher**（来自 [[DAPO]]）：解耦 PPO clip 的上下界为 $\varepsilon_{\text{low}} = 0.2$ 和 $\varepsilon_{\text{high}} = 0.28$。放宽上界给低概率 token 更多增长空间（鼓励探索），保持下界较小避免将 token 概率压到 0（防止 [[Entropy Collapse]]）。

**Positive Example LM Loss**（Self-Imitation Learning 思想）：对 RL 训练中采样到的正确答案，额外施加 NLL loss：

$$\mathcal{L}_{\text{NLL}}(\theta) = -\frac{1}{\sum_{o_i \in \mathcal{T}} |o_i|} \sum_{o_i \in \mathcal{T}} \sum_{t=1}^{|o_i|} \log \pi_{\theta}(a_t | s_t)$$

其中 $\mathcal{T}$ 是正确答案的集合。最终 loss 为 $\mathcal{L} = \mathcal{L}_{\text{PPO}} + \mu \cdot \mathcal{L}_{\text{NLL}}$（$\mu = 0.1$）。这本质上是一种 imitation learning，最大化利用稀缺的正确样本。

**Group-Sampling**（来自 [[GRPO]]）：每个 prompt 采样 16 次（而非每个 prompt 采样 1 次），增加在困难问题上采到正确答案的概率。

## 技术栈总览

| 技术 | 来源 | 解决的挑战 | 消融影响 |
|------|------|-----------|---------|
| Value-Pretraining | [[VC-PPO]] | Value model bias | -49 分（最关键） |
| Decoupled-GAE | [[VC-PPO]] | Value model bias | -27 分 |
| **Length-Adaptive GAE** | **VAPO 原创** | Heterogeneous lengths | -15 分 |
| Clip-Higher | [[DAPO]] | Reward sparsity / 探索 | -14 分 |
| Token-Level Loss | [[DAPO]] | Heterogeneous lengths | -7 分 |
| Positive Example LM Loss | SIL 思想 | Reward sparsity | -6 分 |
| Group-Sampling | [[GRPO]] | Reward sparsity | -5 分 |

> [!intuition] 整合的价值
> VAPO 的贡献不仅在于 Length-Adaptive GAE 这一新方法，更在于**系统性地识别了 long-CoT RL 的三大挑战，并为每个挑战组合了最合适的解决方案**。消融实验证明每个组件都有独立贡献，且组合效果大于各部分之和（vanilla PPO 仅 5 分 → VAPO 60 分）。

## 实验亮点

**主要结果**（AIME 2024, avg@32, Qwen2.5-32B base）：

| 方法 | 分数 |
|------|------|
| Vanilla PPO | 5 |
| DeepSeek-R1-Zero-Qwen-32B | 47 |
| DAPO | 50 |
| **VAPO** | **60.4** |

**训练特性**：
- 5000 步即达到 SOTA，效率显著优于 DAPO
- 多次独立运行无 crash，训练曲线平滑
- 无需 SFT 数据，直接从 pretrained model 开始 RL
- Entropy 下降比 DAPO 更低但更稳定，牺牲少量探索换取可复现性

## 局限性

> [!warning] 需要注意的边界
> - **Value model 的额外开销**：相比 value-model-free 方法，VAPO 需要训练和维护一个额外的 value model，增加了显存和计算成本
> - **Value-Pretraining 的前置成本**：需要 50 步的 value model warmup，这是一个不可省略的前置步骤
> - **仅验证了数学推理**：论文实验集中在 AIME 2024，对 code、science 等其他推理任务的泛化性有待验证
> - **$\alpha$ 超参数的选择**：Length-Adaptive GAE 中的 $\alpha = 0.05$ 是否对不同任务/模型通用，论文未充分讨论

> [!interview] 面试视角
> **Q: VAPO 相比 DAPO/GRPO 的核心优势是什么？**
> A: VAPO 是 value-model-based 方法，能提供 token-level 的精细 credit assignment，而 DAPO/GRPO 只能做 trajectory-level 的粗粒度优化。关键创新是 Length-Adaptive GAE，让 $\lambda$ 随序列长度自适应调整，解决了固定 $\lambda$ 在 long-CoT 场景下的 bias-variance 失衡问题。
>
> **Q: 为什么 Value-Pretraining 如此关键？**
> A: 因为 value model 从 reward model 初始化，而两者目标不同（reward model 只在 EOS 打分，value model 需要估计每个位置的期望回报）。不做预训练的话，初始偏差会通过 GAE 的 bootstrapping 累积放大，导致训练直接崩溃。
