# MEM1 (2025)

MEM1（Memory-Efficient Mechanism via learning 1-step integrated reasoning and consolidation）是一个端到端强化学习框架，使 LLM agent 能够在长时程多轮任务中以恒定内存运行。核心创新是将推理（reasoning）和记忆整合（memory consolidation）统一到一个共享的内部状态（internal state）中，在每轮交互后丢弃历史上下文，仅保留压缩后的状态。在 16 目标多跳 QA 任务上，MEM1-7B 相比 Qwen2.5-14B-Instruct 实现 3.5 倍性能提升，同时内存使用降低 3.7 倍。

## 动机：长时程 Agent 的三重挑战

现有 LLM agent 系统（如 [[ASTRA]]、Deep Researcher）在处理长时程多轮任务时，通常将所有历史观察、动作、思考过程追加到上下文中。这种"无限增长上下文"的做法带来三个核心问题：

1. **推理成本和内存使用线性增长**：Transformer 的 $O(N^2)$ 计算复杂度（或 KV cache 的 $O(N)$ 内存）导致 GPU 内存需求随交互轮数爆炸式增长
2. **超出训练长度的泛化失败**：当对话长度超过训练数据分布时，模型进入 OOD 状态，推理能力急剧下降
3. **上下文过载降低推理效率**：无关或冗余信息稀释注意力，即使相关信息仍在上下文中，模型也难以有效利用

> [!intuition] 核心洞察
> 人类在长时程任务中不会记住所有细节，而是**选择性地保留关键信息**并**整合到工作记忆**中。MEM1 将这一认知机制形式化为 RL 训练目标：让模型学会在推理过程中同时完成记忆整合。

## 核心机制：统一的内部状态

### 内部状态的设计

MEM1 使用 XML 标签结构化 agent 的交互循环：

- `<IS>` (Internal State)：整合了历史记忆和当前推理的内部状态
- `<query>`：向环境发出的查询（如搜索请求）
- `<answer>`：agent 的最终回答
- `<info>`：环境返回的观察结果

在每轮 $t$，agent 的行为流程：

1. **生成新内部状态**：$\text{<IS}_t\text{>}$ 整合 $(\text{<IS}_{t-1}\text{>}, \text{<query}_{t-1}\text{>}, \text{<info}_{t-1}\text{>})$
2. **决策动作**：生成 $\text{<query}_t\text{>}$（继续交互）或 $\text{<answer}_t\text{>}$（结束任务）
3. **接收反馈**：环境返回 $\text{<info}_t\text{>}$
4. **丢弃历史**：删除 $t-1$ 轮的所有标签，仅保留 $\text{<IS}_t\text{>}$

> [!example] 内存演化示例
> ```
> Turn 1: [Prompt] + <IS_1> + <query_1> + <info_1>
> Turn 2: [Prompt] + <IS_2> + <query_2> + <info_2>  # <IS_1>, <query_1>, <info_1> 已删除
> Turn 3: [Prompt] + <IS_3> + <answer_3>            # <IS_2>, <query_2>, <info_2> 已删除
> ```
>
> 任意时刻，上下文中最多保留：2 个 `<IS>`、2 个 `<query>`、1 个 `<info>`，实现近恒定内存。

### RL 训练如何驱动记忆整合

MEM1 没有显式优化"内存效率"的奖励信号，而是通过任务成功奖励**隐式地**学习记忆整合：

- **环境设计**：构造需要多轮交互才能完成的任务（如多目标 QA）
- **上下文裁剪**：强制删除历史上下文，agent 无法"作弊"回看完整历史
- **奖励信号**：只有在最终回答正确时才给予奖励

这种设计迫使 agent 学会在 `<IS>` 中保留关键信息，否则无法获得奖励。类似人类通过数独、填字游戏训练记忆能力——成功依赖于选择性注意和信息整合。

## 训练方法：Masked Trajectory for Policy Optimization

### 挑战：动态上下文破坏轨迹连续性

传统 RL 算法（如 [[PPO]]、[[REINFORCE++]]）假设轨迹是线性的 token 序列。但 MEM1 在每轮交互后**动态修改上下文**（删除历史 token），导致：

- 无法直接计算 token-wise advantage
- 策略梯度估计需要考虑"哪些 token 在生成时可见"

### 解决方案：2D Attention Mask

MEM1 提出 **masked trajectory** 方法：

1. **重构完整轨迹**：将多轮交互拼接为统一序列 $\tau = (\tau_1, \tau_2, \ldots, \tau_T)$，其中 $\tau_t = (\text{<IS}_t\text{>}, \text{<query}_t\text{>}, \text{<info}_t\text{>})$
2. **应用 2D attention mask**：对于位置 $k$ 的 token，mask 掉所有"在生成时不可见"的历史 token
3. **计算策略比率**：$\rho_k(\theta) = \frac{\pi_\theta(a_k|s_k)}{\pi_{\theta_{\text{old}}}(a_k|s_k)}$，其中 $s_k$ 是 masked 后的输入状态

此外，借鉴 [[ASTRA]] 的做法，在策略更新时应用 **1D information mask**，确保梯度只作用于 agent 生成的 token（而非环境返回的 `<info>`）。

> [!math] 策略梯度计算
> 对于 token $k$，其 advantage $A_k$ 基于 masked 状态 $s_k$ 计算：
> $$
> \nabla_\theta J(\theta) = \mathbb{E}_{\tau \sim \pi_{\theta_{\text{old}}}} \left[ \sum_{k} \nabla_\theta \log \pi_\theta(a_k | s_k) \cdot A_k \right]
> $$
> 其中 $s_k$ 只包含"在生成 $a_k$ 时可见的 token"。

## 任务增强：Multi-Objective Task Augmentation

### 现有数据集的局限

现有多跳 QA 数据集（如 [[HotpotQA]]、2wiki）通常只需 2 步信息检索，不足以训练长时程 agent。

### 解决方案：组合式任务构造

MEM1 提出简单但有效的任务增强方法：

1. **从单目标数据集采样 $N$ 个问题**：如从 HotpotQA 采样 2 个问题
2. **组合为复合查询**：要求 agent 回答所有子问题
3. **奖励设计**：只有所有子问题都正确才给予奖励

这种方法将交互轮数从 2-3 轮扩展到 $2N$ 轮以上，显著增加任务复杂度。

> [!example] 2-Objective Task 示例
> ```
> 原始问题 1: "NVIDIA L40S 的 TDP 是多少？"
> 原始问题 2: "A100 的内存带宽是多少？"
>
> 组合查询: "比较 NVIDIA L40S 和 A100 GPU，哪个更适合高吞吐量深度学习工作负载？
>           请分别回答：(1) L40S 的 TDP；(2) A100 的内存带宽。"
> ```

## 实验结果

### Multi-Objective Multi-Hop QA

在 2/8/16 目标任务上的表现（训练仅在 2 目标数据上）：

| 模型 | 2-Obj EM | 8-Obj EM | 16-Obj EM | 16-Obj Peak Tokens | 16-Obj Time (s) |
|------|----------|----------|-----------|-------------------|-----------------|
| Qwen2.5-14B-Inst | 0.732 | 1.55 | 0.567 | 38.4k | 29.7 |
| Qwen2.5-7B-Inst | 0.268 | 0.87 | 0.165 | 43.3k | 15.5 |
| MEM1-7B | **0.709** | **1.87** | **1.97** | **10.4k** | **8.70** |

关键发现：
- **泛化能力**：在 2 目标数据上训练，泛化到 16 目标（8 倍长度）
- **效率提升**：相比 Qwen2.5-14B，内存降低 3.7 倍，速度提升 3.4 倍
- **性能反超**：在 16 目标任务上，7B 的 MEM1 超越 14B 的 Instruct 模型

### WebShop Navigation

在多轮购物任务上：

| 模型 | Reward | Peak Tokens | Dependency | Time (s) |
|------|--------|-------------|------------|----------|
| AgentLM-7B | 0.571 | 14.2k | 9.8k | 6.1 |
| MEM1-7B | **0.582** | **5.1k** | **5.2k** | **4.1** |

MEM1 实现 2.8 倍内存降低、1.9 倍依赖长度降低、1.5 倍速度提升。

### Zero-Shot Transfer

MEM1 在 Wikipedia QA 上训练，零样本迁移到 Online Web QA：

- **效率保持**：Peak tokens 降低 2.3 倍
- **性能保持**：F1 score 与 Qwen2.5-14B 相当

## 涌现行为分析

通过分析 `<IS>` 的内容，发现 MEM1 学会了三类策略：

1. **多目标管理**：显式追踪"已完成 X 个目标，还需完成 Y 个"
2. **记忆整合**：将检索到的信息压缩为关键事实（如"L40S TDP: 350W"）
3. **搜索策略**：根据问题类型调整查询（如"需要对比 → 先分别搜索 → 再综合"）

> [!example] 内部状态示例
> ```
> <IS>
> 已完成目标 1/2。
> 目标 1 答案：L40S 的 TDP 是 350W。
> 目标 2：需要查询 A100 的内存带宽。
> 下一步：搜索 "A100 memory bandwidth"。
> </IS>
> ```

## 局限性与未来方向

> [!warning] 当前局限
> 1. **训练成本**：RL 训练需要大量环境交互（虽然比 full-context 方法更高效）
> 2. **任务特定性**：需要为不同任务设计合适的奖励信号
> 3. **内部状态长度**：当前 `<IS>` 长度固定，未来可探索动态长度
> 4. **多模态扩展**：当前仅支持文本，未来可扩展到视觉、音频等模态

**未来方向**：
- 探索 [[Process Reward Model]] 提供更细粒度的信用分配
- 结合 [[On-Policy Distillation]] 降低训练成本
- 研究 hierarchical internal state（多层记忆结构）

## 相关工作对比

| 方法 | 记忆管理 | 训练方式 | 内存复杂度 |
|------|----------|----------|-----------|
| ReAct | 追加所有历史 | Prompting | $O(N)$ |
| [[ASTRA]] | 追加所有历史 | SFT + RL | $O(N)$ |
| A-MEM | 外部 summarizer | 独立训练 | $O(1)$ |
| **MEM1** | 统一内部状态 | 端到端 RL | $O(1)$ |

MEM1 的优势：
- **端到端优化**：记忆整合与任务目标联合优化，无需额外模块
- **零架构修改**：仅通过 RL 训练实现，无需改变模型结构
- **泛化能力强**：训练长度 → 测试长度 8 倍泛化
