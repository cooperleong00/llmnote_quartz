# Data Synthesis

Data Synthesis（数据合成）是指**使用模型生成训练数据**的方法族。核心动机是解决高质量人类数据的三大瓶颈：**稀缺**（专业领域数据有限）、**昂贵**（人工标注成本高）、**难以扩展**（标注速度跟不上模型迭代）。数据合成已成为现代 LLM post-training 的核心技术，从 [[SFT]] 数据生成到 [[RLAIF]] 的偏好标注，几乎每个环节都依赖合成数据。

---

## 动机

> [!intuition] 为什么需要数据合成？
> 想象你要训练一个数学推理模型：
> - **人类数据**：请数学家写 10 万道题的详细解答 → 成本数百万美元，耗时数月
> - **合成数据**：让 GPT-4 生成 100 万道题的解答 → 成本数千美元，耗时数天
>
> 关键洞察：**模型已经具备生成高质量数据的能力**，为什么不利用它？

### 人类数据的瓶颈

| 瓶颈 | 具体表现 | 影响 |
|------|----------|------|
| **稀缺性** | 专业领域（医学、法律、代码）数据有限 | 模型在专业任务上表现差 |
| **成本** | 高质量标注需要专家，每条数据成本高 | 数据规模受限 |
| **扩展性** | 人工标注速度慢，跟不上模型迭代 | 训练周期长 |
| **一致性** | 不同标注者判断不一致 | 数据噪声大 |
| **心理负担** | 标注有害内容对标注者有负面影响 | 安全数据难以获取 |

## 核心方法

数据合成方法可以按**生成目标**和**监督来源**分类：

```
┌─────────────────────────────────────────────────────────────────┐
│                     Data Synthesis 方法族                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  按生成目标分类：                                                 │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐              │
│  │ 指令数据     │  │ 偏好数据     │  │ 验证数据     │              │
│  │ (SFT 用)    │  │ (RM/DPO 用) │  │ (过滤用)    │              │
│  └─────────────┘  └─────────────┘  └─────────────┘              │
│                                                                 │
│  按监督来源分类：                                                 │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐              │
│  │ 自我生成     │  │ 教师蒸馏     │  │ 规则验证     │              │
│  │ Self-*      │  │ Distillation│  │ Verifiable  │              │
│  └─────────────┘  └─────────────┘  └─────────────┘              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1. Self-Instruct / Self-Play

**核心思想**：让模型自己生成指令和回答，形成自我改进循环。

**Self-Instruct 流程**：
1. 从少量种子指令出发
2. 让模型生成新指令（多样化）
3. 让模型为新指令生成回答
4. 过滤低质量数据
5. 用生成的数据训练模型

> [!example] Self-Instruct 的典型应用
> - **Alpaca**：用 175 条种子指令，让 GPT-3.5 生成 52K 指令数据
> - **WizardLM**：通过 Evol-Instruct 逐步增加指令复杂度
> - **Self-Reward**：模型同时生成回答和评分，形成自我奖励循环

**Self-Play 变体**：
- 模型与自己对弈（如辩论、角色扮演）
- 生成多个候选回答，互相评估
- 用于生成对抗性数据和边界案例

### 2. Distillation（知识蒸馏）

**核心思想**：从强模型（教师）生成数据，训练弱模型（学生）。

这是目前最常用的数据合成方式，详见 [[On-Policy Distillation]]。

**典型流程**：
```
强模型（GPT-4, Claude）→ 生成高质量回答 → 训练弱模型（Llama, Qwen）
```

**关键变体**：

| 方法 | 特点 | 代表工作 |
|------|------|----------|
| **Off-Policy Distillation** | 在教师生成的数据上训练 | 传统 KD |
| **[[On-Policy Distillation]]** | 学生采样，教师提供 token-level 监督 | GKD, OPSD |
| **[[MOPD]]** | 多教师在线蒸馏，领域专家分工 | Kimi K2 |

> [!warning] 蒸馏的法律风险
> 许多闭源模型（如 GPT-4）的使用条款禁止用其输出训练竞争模型。实际操作中需要注意合规性。

### 3. RLAIF（AI 生成偏好标签）

**核心思想**：用 AI 替代人类进行偏好标注，详见 [[RLAIF]]。

```
RLHF:  模型生成多个回答 → 人类标注偏好 → 训练 Reward Model
RLAIF: 模型生成多个回答 → AI 标注偏好  → 训练 Reward Model
```

**优势**：
- 成本降低 10-100 倍
- 标注一致性更高
- 可以处理人类难以判断的专业内容

**应用**：[[Constitutional AI]] 的第二阶段就是典型的 RLAIF 应用。

### 4. Rejection Sampling / Best-of-N

**核心思想**：生成多个候选，选择最好的作为训练数据。

**流程**：
1. 对每个 prompt，让模型生成 N 个回答
2. 用 Reward Model 或规则评估每个回答
3. 选择得分最高的作为正样本
4. 用选出的数据进行 [[SFT]] 或偏好训练

> [!math] Rejection Sampling 的数学本质
> 设模型分布为 $\pi(y|x)$，奖励函数为 $r(x, y)$，则 Best-of-N 采样近似于：
> $$\pi_{\text{BoN}}(y|x) \propto \pi(y|x) \cdot \exp(r(x, y) / \beta)$$
> 这与 [[RLHF]] 的最优策略形式一致，但不需要 RL 训练。

**典型应用**：
- **RFT (Rejection Sampling Fine-Tuning)**：DeepSeekMath 用此方法生成数学推理数据
- **Online RFT**：实时从当前策略采样，而非固定的 SFT 模型

### 5. Constitutional AI 的自我改进

**核心思想**：让模型根据预定义原则批评和修正自己的输出，详见 [[Constitutional AI]]。

**Critique & Revision 流程**：
1. 生成可能有害的回答
2. 让模型根据"宪法原则"批评自己
3. 让模型修正回答
4. 用修正后的数据进行 SFT

> [!intuition] 为什么自我批评有效？
> 模型"知道"什么是好的回答（通过预训练学到的知识），但在直接生成时可能不会遵循。
> 通过显式的批评-修正过程，可以"激活"这些知识，生成更高质量的数据。

## 数据质量控制

合成数据的核心挑战是**质量控制**——模型生成的数据可能包含错误、重复、或低质量内容。

### 过滤策略

| 策略 | 方法 | 适用场景 |
|------|------|----------|
| **规则过滤** | 长度、格式、关键词检查 | 基础质量控制 |
| **模型过滤** | 用 Reward Model 或 LLM-as-Judge 评分 | 语义质量控制 |
| **验证过滤** | 用外部工具验证（代码执行、数学验证） | 可验证任务 |
| **去重** | 语义相似度去重 | 多样性保证 |

### 多样性保证

> [!warning] 多样性陷阱
> 合成数据容易陷入"模式坍缩"——生成的数据高度相似，缺乏多样性。

**解决方案**：
- **Temperature 调节**：提高采样温度增加多样性
- **Prompt 多样化**：使用不同的 prompt 模板
- **种子多样化**：从多样的种子数据出发
- **对抗生成**：专门生成边界案例和困难样本

### 可验证任务的优势

对于**可验证任务**（数学、代码、逻辑推理），数据质量控制更容易：

```
数学题 → 模型生成解答 → 验证答案是否正确 → 只保留正确的
代码题 → 模型生成代码 → 执行测试用例 → 只保留通过的
```

这也是为什么 reasoning model（如 DeepSeek-R1）在数学和代码上进展最快——**可验证性提供了天然的质量过滤器**。

## 与 Post-training Pipeline 的关系

数据合成贯穿整个 post-training 流程：

```
┌─────────────────────────────────────────────────────────────────┐
│                    Post-training Pipeline                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Stage 1: SFT                                                   │
│  ├─ Self-Instruct 生成指令数据                                   │
│  ├─ Distillation 从强模型蒸馏                                    │
│  └─ Constitutional AI 的 Critique & Revision                    │
│                                                                 │
│  Stage 2: Reward Model                                          │
│  ├─ RLAIF 生成偏好标签                                           │
│  └─ Best-of-N 生成对比数据                                       │
│                                                                 │
│  Stage 3: RL / Direct Alignment                                 │
│  ├─ Rejection Sampling 生成高质量数据                            │
│  ├─ On-Policy Distillation 提供 token-level 监督                │
│  └─ Self-Play 生成对抗数据                                       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 局限性与风险

### 1. Model Collapse（模型坍缩）

> [!warning] 核心风险
> 如果模型持续在自己生成的数据上训练，可能导致**分布退化**——多样性下降，错误累积。

**机制**：
- 模型生成的数据反映其当前能力的"平均水平"
- 训练在这些数据上会强化"平均"行为，抑制"尾部"能力
- 多代迭代后，模型能力逐渐退化

**缓解策略**：
- 混合人类数据和合成数据
- 定期引入新的种子数据
- 使用外部验证器过滤

### 2. Bias Amplification（偏见放大）

**问题**：模型的偏见会在合成数据中被放大。

**示例**：
- 如果模型对某些群体有偏见，生成的数据会强化这种偏见
- 训练在这些数据上会进一步加剧偏见

**缓解策略**：
- 多样化的 prompt 设计
- 偏见检测和过滤
- 人类审核关键数据

### 3. 能力天花板

> [!intuition] 学生能超过老师吗？
> 理论上，蒸馏的学生模型能力上限是教师模型。但实际中：
> - **可验证任务**：通过 rejection sampling，学生可以超过教师（只保留正确的）
> - **不可验证任务**：学生很难超过教师

**突破天花板的方法**：
- 使用可验证的奖励信号（数学、代码）
- 多教师集成（不同教师擅长不同领域）
- 结合 RL 探索新策略

### 4. 数据污染

**问题**：合成数据可能包含测试集信息（如果教师模型见过测试集）。

**缓解策略**：
- 使用 held-out 测试集
- 检测数据泄露
- 使用时间戳隔离

## 面试要点

> [!interview] 常见问题
>
> **Q1: 数据合成的主要方法有哪些？**
> A: 主要包括：(1) Self-Instruct/Self-Play——模型自我生成指令和回答；(2) Distillation——从强模型蒸馏到弱模型；(3) RLAIF——AI 生成偏好标签；(4) Rejection Sampling——生成多个候选选最好的；(5) Constitutional AI——自我批评和修正。
>
> **Q2: Model Collapse 是什么？如何避免？**
> A: Model Collapse 是指模型在自己生成的数据上持续训练导致的分布退化——多样性下降，错误累积。避免方法：混合人类数据、定期引入新种子、使用外部验证器过滤。
>
> **Q3: 为什么 reasoning model 在数学和代码上进展最快？**
> A: 因为这些任务是**可验证的**——可以通过执行代码或验证答案来判断正确性。这提供了天然的质量过滤器，使得 rejection sampling 等方法非常有效。
>
> **Q4: 蒸馏的学生能超过教师吗？**
> A: 在可验证任务上可以——通过 rejection sampling 只保留正确答案，学生可以超过教师的平均水平。在不可验证任务上很难，因为缺乏客观的质量判断标准。
