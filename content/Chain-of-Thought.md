# Chain-of-Thought

思维链（Chain-of-Thought, CoT）是一种让 LLM 在生成最终答案前先显式生成中间推理步骤的技术。核心思想是：复杂问题直接回答容易出错，通过"让模型说出思考过程"能显著提升准确性。CoT 既是推理时的提示技术，也是训练时的数据范式。

## 动机

> [!intuition] 为什么需要 CoT？
> 人类解决复杂问题时会"边想边说"——把大问题分解成小步骤，每步验证正确性。LLM 直接输出答案时，缺少这个"思考过程"的约束，容易跳步或出错。
>
> **问题**：数学题"Roger 有 5 个网球。他又买了 2 罐网球，每罐 3 个。他现在有多少个网球？"
> 
> **直接回答**（容易出错）：
> - 模型可能直接输出"11 个"（5+2+3，错误地把罐数当球数）
> 
> **CoT 回答**（显式推理）：
> - "Roger 开始有 5 个球。他买了 2 罐，每罐 3 个，所以是 2×3=6 个新球。总共 5+6=11 个球。"
> - 推理步骤强制模型"慢下来"，减少跳步错误

**核心洞察**：
1. **计算约束**：生成推理步骤增加了计算量（更多 token），给模型更多"思考时间"
2. **结构化输出**：推理链提供了可验证的中间结果
3. **隐式知识激活**：逐步推理能激活训练时学到的相关知识

## 核心机制

### Few-shot CoT（原始方法）

在 prompt 中提供带推理步骤的示例，引导模型模仿：

> [!example] Few-shot CoT Prompt
> ```
> Q: Roger 有 5 个网球。他又买了 2 罐网球，每罐 3 个。他现在有多少个网球？
> A: Roger 开始有 5 个球。他买了 2 罐，每罐 3 个，所以是 2×3=6 个新球。
>    总共 5+6=11 个球。答案是 11。
> 
> Q: [新问题]
> A: [模型生成推理链]
> ```

**关键要素**：
- 示例中包含完整的推理步骤（不只是答案）
- 推理步骤用自然语言表达（不是形式化符号）
- 最后明确给出答案

### Zero-shot CoT（更简单的变体）

不需要示例，只需在问题后加一句提示：

> [!example] Zero-shot CoT
> ```
> Q: [问题]
> A: Let's think step by step.
> ```

**惊人发现**：这个简单的提示就能激活模型的推理能力，在很多任务上接近 few-shot CoT 的效果。

**为什么有效**：
- 预训练数据中包含大量"逐步解释"的文本（教程、解题过程等）
- "Let's think step by step" 激活了这些模式
- 模型学会了"慢思考"的行为模式

## 在 LLM 训练中的应用

CoT 不只是推理时的技巧，更是训练数据的重要组成部分：

### SFT 阶段：建立推理模式

在 [[SFT]] 阶段注入 CoT 数据，让模型学会"边想边说"：

```
训练数据格式：
{
  "instruction": "解决这个数学问题：...",
  "output": "[推理步骤]\n因此答案是 [最终答案]"
}
```

**数据来源**：
- 人工标注的推理链
- 从强模型（如 GPT-4）蒸馏的推理过程
- 合成数据（用代码生成数学题 + 推理步骤）

### RL 阶段：强化正确推理

在 RL 训练中，CoT 数据提供了**可验证的奖励信号**：

- **[[GRPO]]** 等算法常用 GSM8K、MATH 等 CoT 数据集训练
- 推理步骤让 reward 更精确（不只看最终答案，也看推理质量）
- 例：DeepSeek-R1 用大量 CoT 数据训练出强推理能力

> [!example] GRPO 中的 CoT 使用
> GRPO 论文中，只用 GSM8K（数学推理）和 MATH（高级数学）两个 CoT 数据集训练，就能显著提升模型的推理能力。这些数据集的特点是：
> - 每个问题都有详细的解题步骤
> - 最终答案可以自动验证（数学题有标准答案）
> - 推理链长度适中（几百个 token）

### Mid-training：预激活推理能力

在 pretraining 和 SFT 之间，用 CoT 数据做 mid-training：

- 让模型在正式指令微调前就熟悉"逐步推理"的模式
- 提升后续 SFT 和 RL 的效率

## 变体与扩展

### Self-Consistency（多次采样投票）

生成多个推理链，用多数投票选择答案：

```
同一问题 → 采样 N 次（temperature > 0）→ 得到 N 个推理链
→ 提取 N 个答案 → 多数投票 → 最终答案
```

**为什么有效**：
- 不同推理路径可能犯不同错误
- 正确答案更可能在多条路径中出现
- 类似"集成学习"的思想

**代价**：推理成本增加 N 倍（通常 N=5~40）

### Tree-of-Thought（搜索式推理）

将推理建模为树搜索：

```
问题 → 生成多个可能的第一步 → 评估每步的质量
     → 选择最优的几步继续展开 → 递归搜索
     → 找到最优推理路径
```

**适用场景**：
- 需要探索多种可能性的问题（如游戏、规划）
- 中间步骤的质量可以评估

**局限**：计算成本极高（指数级搜索空间）

### Program-aided CoT

用代码而非自然语言表达推理步骤：

```
Q: Roger 有 5 个网球...
A: 
# Roger 开始有 5 个球
initial_balls = 5
# 他买了 2 罐，每罐 3 个
cans = 2
balls_per_can = 3
new_balls = cans * balls_per_can
# 总共
total = initial_balls + new_balls
print(total)  # 11
```

**优势**：
- 代码可以直接执行，验证正确性
- 避免自然语言的歧义
- 适合数学、逻辑等形式化任务

## 局限性

> [!warning] CoT 的边界
> 
> **1. 推理成本增加**
> - 生成推理链需要更多 token（通常 2-5 倍）
> - 推理时间和成本显著增加
> - Self-Consistency 等变体成本更高
> 
> **2. 可能产生错误的推理链**
> - 推理步骤看起来合理，但逻辑有误
> - "幻觉"问题在推理链中也存在
> - 错误的推理链可能误导后续步骤
> 
> **3. 不是所有任务都需要 CoT**
> - 简单的事实性问题（"法国首都是哪里？"）不需要推理
> - 过度使用 CoT 浪费计算资源
> - 需要根据任务复杂度选择是否使用
> 
> **4. 推理链的质量依赖训练数据**
> - 如果训练数据中推理链质量差，模型学到的也是差的推理模式
> - 需要高质量的 CoT 数据（人工标注或强模型蒸馏）

## 实践建议

> [!example] 何时使用 CoT
> 
> **适合 CoT 的任务**：
> - 数学推理（GSM8K, MATH）
> - 逻辑推理（需要多步推导）
> - 代码生成（需要规划和分解）
> - Agent 任务规划（需要分解子目标）
> 
> **不适合 CoT 的任务**：
> - 简单的事实性问答
> - 分类任务（情感分析、主题分类）
> - 需要快速响应的场景（成本敏感）
> 
> **训练时的 CoT 数据配比**：
> - SFT 阶段：10-30% CoT 数据（不要全是 CoT，保持多样性）
> - RL 阶段：可以专注于 CoT 数据（如 GRPO 只用推理数据集）
> - 数据质量 > 数量（宁可少而精）

> [!interview] 面试要点
> 
> **Q: CoT 为什么能提升推理能力？**
> A: 三个层面：
> 1. **计算层面**：更多 token = 更多计算 = 更多"思考时间"
> 2. **结构层面**：推理步骤提供可验证的中间结果，减少跳步错误
> 3. **知识层面**：逐步推理激活训练时学到的相关知识
> 
> **Q: Zero-shot CoT 为什么只需要 "Let's think step by step" 就有效？**
> A: 预训练数据中包含大量"逐步解释"的文本（教程、解题过程等），这句话激活了模型学到的"慢思考"模式。本质上是利用了预训练时的隐式知识。
> 
> **Q: CoT 在训练中如何使用？**
> A: 三个阶段：
> 1. **SFT**：注入 CoT 数据建立推理模式（10-30% 配比）
> 2. **RL**：用 CoT 数据集（如 GSM8K）训练，可验证的奖励信号
> 3. **Mid-training**：预激活推理能力，提升后续训练效率
> 
> **Q: CoT 的主要局限是什么？**
> A: 
> 1. 推理成本高（2-5 倍 token）
> 2. 可能产生看似合理但错误的推理链
> 3. 不是所有任务都需要（简单问题浪费资源）
> 4. 质量依赖训练数据（需要高质量 CoT 数据）
> 
> **Q: Self-Consistency 和 CoT 的关系？**
> A: Self-Consistency 是 CoT 的增强版：对同一问题生成多个 CoT 推理链（采样多次），然后用多数投票选择最终答案。优势是更鲁棒（不同推理路径的错误可能不同），代价是推理成本增加 N 倍。
