# Kimi K2.5 (2026)

Kimi K2.5 是月之暗面发布的原生多模态智能体模型，核心创新在于**联合优化文本和视觉**使两种模态相互增强，以及 **Agent Swarm** 并行智能体编排框架。模型在 [[Kimi K2 (2025)|Kimi K2]] 基础上通过 15T 混合视觉-文本 token 的联合预训练构建，实现了跨模态能力迁移——视觉 RL 训练反而提升了文本性能。

> [!paper] 论文信息
> - **标题**: Technical Report of Kimi K2.5
> - **机构**: 月之暗面（Moonshot AI）
> - **发布时间**: 2026 年 2 月
> - **arXiv**: 2602.02276
> - **开源**: 已发布 post-trained checkpoint

## 核心贡献

### 1. 联合文本-视觉优化

K2.5 的核心洞察是**文本和视觉的联合优化能够相互增强**，而非相互妥协。这一理念贯穿预训练、SFT 和 RL 三个阶段。

#### 原生多模态预训练

> [!intuition] 反直觉的发现
> 传统观点认为应该在训练后期以高比例（50%+）引入视觉 token，将多模态能力视为语言能力的"后置附加"。
> 
> K2.5 的实验发现：**早期融合 + 低视觉比例**（10%）在固定总 token 预算下效果更好。

**实验结果**（固定总 vision-text token 预算）：

| 策略 | 视觉注入时机 | 视觉:文本比例 | 视觉推理 | 文本推理 | 代码 |
|------|-------------|--------------|---------|---------|------|
| 早期融合 | 0% | 10%:90% | 43.8 | 58.5 | 24.8 |
| 中期融合 | 50% | 20%:80% | 40.7 | 58.6 | 24.0 |
| 后期融合 | 80% | 50%:50% | 39.0 | 57.8 | 24.0 |

**设计选择**：采用适度的视觉比例，从训练早期就开始整合，让模型自然发展平衡的多模态表征。

#### Zero-Vision SFT

> [!intuition] 核心思想
> 用**纯文本 SFT 数据**激活视觉智能体能力，所有图像操作通过 IPython 程序化操作代理。

**动机**：
- 预训练 VLM 不会自然地进行基于视觉的工具调用（冷启动问题）
- 传统方法依赖人工标注或 prompt 工程的 CoT 数据，多样性有限
- 高质量文本 SFT 数据相对丰富且多样

**关键发现**：
- Zero-vision SFT 足以激活视觉能力，同时确保跨模态泛化
- 文本-视觉 SFT 在视觉智能体任务上表现更差（可能因缺乏高质量视觉数据）
- 这一现象归功于第 2.1 节的联合预训练建立的强视觉-文本对齐

#### 联合多模态强化学习

**基于结果的视觉 RL**：

在 zero-vision SFT 之后，模型需要进一步优化以可靠地将视觉输入融入推理。K2.5 在明确需要视觉理解的任务上使用基于结果的 RL：
- 视觉定位和计数
- 图表和文档理解
- 需要视觉输入的 STEM 问题

**跨模态迁移**：视觉 RL 提升文本性能

> [!intuition] 反直觉的发现
> 视觉 RL 不仅没有损害文本能力，反而在纯文本基准上产生了可测量的提升。

| 基准 | 视觉 RL 前 | 视觉 RL 后 | 提升 |
|------|-----------|-----------|------|
| MMLU-Pro | 84.7% | 86.4% | +1.7% |
| GPQA-Diamond | 84.3% | 86.4% | +2.1% |
| LongBench v2 | 56.7% | 58.9% | +2.2% |

**原因分析**：视觉 RL 增强了结构化信息提取领域的校准能力，减少了类似视觉基础推理（如计数、OCR）的查询的不确定性。

**联合 RL 范式**：

受此发现启发，K2.5 在 post-training 期间采用联合多模态 RL 范式：
- **不按输入模态划分**（文本 vs 视觉），而是**按能力划分**（知识、推理、编码、智能体等）
- 领域专家从纯文本和多模态查询中共同学习
- [[Generative Reward Model|GRM]] 同样跨异构轨迹优化，无模态障碍
- 确保通过任一模态获得的能力提升自然泛化到另一模态

### 2. Agent Swarm：并行智能体编排

#### 动机：顺序执行的瓶颈

现有智能体系统依赖**顺序执行**推理和工具调用步骤。这在简单、短期任务中有效，但随着任务复杂度增加和累积上下文增长，顺序系统遇到显著瓶颈：
- 单个智能体逐步执行会耗尽实际推理深度和工具调用预算
- 推理时间线性扩展，导致不可接受的延迟
- 限制了任务复杂度

#### Agent Swarm 架构

> [!intuition] 核心思想
> 不依赖顺序推理链或预设的并行化启发式，而是通过**动态任务分解、子智能体实例化和并行子任务调度**来执行任务。
>
> 关键：并行化不是预设的优势，而是通过环境反馈和 RL 驱动的探索**显式学习**何时、如何并行化。

**架构设计**：

```
┌─────────────────────────────────────────────┐
│  Trainable Orchestrator（可训练编排器）      │
│  - 学习任务分解策略                          │
│  - 决定是否/何时/如何并行化                   │
│  - 动态创建和调度子智能体                     │
└─────────────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────────┐
│  Frozen Subagents（冻结的子智能体）          │
│  - 来自固定的中间策略检查点                   │
│  - 执行分配的子任务                          │
│  - 输出作为环境观察，不参与梯度更新            │
└─────────────────────────────────────────────┘
```

**为什么解耦架构**：

避免端到端联合优化的两个根本挑战：
1. **信用分配歧义**：正确的最终答案不保证子智能体执行完美，失败也不意味着所有子智能体都错误
2. **训练不稳定**：基于结果的奖励本质上稀疏且有噪声

通过冻结子智能体，将高层协调逻辑与低层执行能力解耦，实现更稳健的收敛。

#### Parallel Agent RL (PARL)

**PARL 奖励函数**：

$$
r = r_{\text{perf}} + \lambda_1 r_{\text{parallel}} + \lambda_2 r_{\text{finish}}
$$

- $r_{\text{perf}}$：评估解决方案的整体成功和质量
- $r_{\text{parallel}}$：激励子智能体实例化，缓解**串行崩溃**（编排器默认单智能体执行的局部最优）
- $r_{\text{finish}}$：奖励成功完成的子任务，防止**虚假并行**（通过生成大量无意义子智能体来刷指标）

超参数 $\lambda_1$ 和 $\lambda_2$ 在训练过程中退火至零，确保最终策略优化主要目标。

**Critical Steps 作为资源约束**：

类比计算图中的关键路径，定义 critical steps 来衡量并行智能体设置中的计算时间成本：

$$
\text{Critical Steps} = \sum_{t=1}^{T} \left( S_{\text{main}}^{(t)} + \max_i S_{\text{sub},i}^{(t)} \right)
$$

- $S_{\text{main}}^{(t)}$：主智能体在阶段 $t$ 的步数
- $S_{\text{sub},i}^{(t)}$：第 $i$ 个子智能体在该并行组中的步数
- 阶段 $t$ 的持续时间由该组中运行时间最长的子智能体决定

通过约束 critical steps 而非总步数，框架显式激励有效的并行化。

**性能提升**：

在广泛搜索场景中，Agent Swarm 相比单智能体基线：
- 推理延迟降低高达 **4.5×**
- Item-level F1 从 72.8% 提升至 79.0%


### 3. 架构与训练基础设施

**模型架构**：
- 基于 [[Kimi K2 (2025)|Kimi K2]] 的 1T 参数 MoE 架构
- **MoonViT-3D**：原生分辨率视觉编码器，采用 NaViT packing 策略，支持可变分辨率图像输入
- **视频理解**：轻量级 3D ViT 压缩机制
  - 连续帧按 4 帧分组
  - 通过共享的 MoonViT 编码器处理
  - 在 patch 级别进行时间平均
  - 在相同上下文窗口内处理长达 4× 的视频，同时保持图像和视频编码器的完全权重共享

**训练基础设施**：
- **Decoupled Encoder Process (DEP)**：解耦编码器进程，优化多模态训练效率

## 评估结果

K2.5 在多个领域达到 SOTA 或接近 SOTA 性能：

**推理与通用能力**：
- MMLU-Pro: 86.4%（视觉 RL 后）
- GPQA-Diamond: 86.4%（视觉 RL 后）
- LongBench v2: 58.9%（视觉 RL 后）

**复杂编码与软件工程**：
- 在内部评估中，视觉到代码生成（image/video-to-code）和真实世界软件工程任务上达到 SOTA

**智能体能力**：
- Agent Swarm 在广泛搜索场景中：
  - 延迟降低 4.5×
  - Item-level F1: 72.8% → 79.0%

**视觉能力**：
- 视觉推理、OCR、图表理解等任务上的强劲表现
- Zero-vision SFT + 视觉 RL 的组合证明有效

## 关键洞察

> [!intuition] 跨模态协同增强
> K2.5 的核心发现是**文本和视觉不是零和博弈**。通过正确的训练策略：
> - 早期联合预训练建立强对齐
> - Zero-vision SFT 利用文本数据激活视觉能力
> - 视觉 RL 反过来提升文本性能
>
> 这种双向增强代表了联合训练中的优越跨模态对齐。

> [!intuition] 学习何时并行化
> Agent Swarm 的关键不是"总是并行化"，而是**学习何时、如何并行化**：
> - 通过 RL 探索发现有效的任务分解策略
> - Critical steps 约束激励真正减少延迟的并行化
> - 辅助奖励防止串行崩溃和虚假并行

## 局限性与未来方向

**当前局限**：
- Agent Swarm 的训练需要精心设计的奖励函数（性能 + 并行 + 完成）
- 解耦架构虽然稳定，但可能限制端到端优化的潜力
- 视觉 RL 提升文本性能的机制尚未完全理解

**未来方向**：
- 探索更大规模的联合多模态预训练
- 研究跨模态迁移的理论基础
- 扩展 Agent Swarm 到更复杂的多智能体协作场景
- 优化 critical steps 约束下的资源分配策略
