# Citation Generation

引用生成（Citation Generation）是 [[RAG]] 系统中的关键机制，将 LLM 的输出归因（attribute）到具体的源文档或片段。核心目标是让生成的内容**可验证**——读者可以追溯到原始来源，判断 LLM 的陈述是否有依据。这直接解决了 LLM 的幻觉问题：没有引用支持的陈述更可能是编造的。

---

## 动机

> [!intuition] 为什么需要引用生成？
>
> **问题**：LLM 会自信地生成看似合理但实际错误的内容（幻觉）。用户无法判断哪些内容可信。
>
> **传统 RAG 的不足**：虽然检索了文档，但生成时可能：
> - 忽略检索内容，依赖参数化知识（可能过时或错误）
> - 混合多个来源，无法区分哪句话来自哪里
> - 生成的内容与检索文档不一致，但用户无从察觉
>
> **Citation Generation 的解决方案**：
> - **可验证性**：每个陈述都标注来源，用户可以点击查看原文
> - **可信度信号**：有引用支持的内容更可信；无引用的内容需谨慎对待
> - **幻觉检测**：如果 LLM 无法为陈述找到支持来源，可能是幻觉

## 核心机制

### 三种主要方法

> [!comparison] 方法对比
>
> | 方法 | 时机 | 优势 | 劣势 |
> |------|------|------|------|
> | **Inline Citation** | 生成时嵌入 | 引用与内容同步生成，自然流畅 | 需要模型原生支持，训练成本高 |
> | **Post-hoc Attribution** | 生成后匹配 | 适用于任何 LLM，无需重新训练 | 可能找不到准确匹配，延迟高 |
> | **Grounded Generation** | 约束生成 | 强制每句话都基于检索内容 | 可能限制表达灵活性，生成质量下降 |

#### 1. Inline Citation（内联引用）

**机制**：训练 LLM 在生成时主动插入引用标记。

**示例输出**：
```
根据研究 [1]，Transformer 使用自注意力机制。
相比 RNN，它能并行处理序列 [2]。

[1] Vaswani et al., 2017
[2] Sutskever et al., 2014
```

**实现方式**：
- 在训练数据中标注引用位置（如 `<cite>1</cite>`）
- 微调 LLM 学习何时、如何插入引用
- 生成时解析引用标记，映射到检索文档

**优势**：引用与内容同步，阅读体验自然
**挑战**：需要大量标注数据，训练成本高

#### 2. Post-hoc Attribution（事后归因）

**机制**：先正常生成回答，再用独立模块为每句话匹配来源。

**流程**：
1. LLM 生成完整回答
2. 将回答拆分为句子或 claim
3. 对每个 claim，在检索文档中搜索支持证据
4. 计算相似度（如 embedding cosine similarity）
5. 为高置信度的 claim 添加引用

**优势**：
- 适用于任何现有 LLM，无需重新训练
- 可以使用专门的归因模型（如 NLI 模型判断蕴含关系）

**挑战**：
- 可能找不到精确匹配（LLM 改写了原文）
- 延迟增加（需要额外的匹配步骤）
- 归因准确性依赖匹配算法质量

#### 3. Grounded Generation（基于事实的生成）

**机制**：约束 LLM 只能基于检索内容生成，每句话都必须有明确来源。

**实现方式**：
- **Constrained Decoding**：在解码时过滤掉与检索内容不一致的 token
- **Retrieval-Augmented Prompting**：在 prompt 中明确要求"仅基于以下文档回答"
- **Fusion-in-Decoder**：将检索文档编码后融合到生成过程

**优势**：强制可验证性，减少幻觉
**挑战**：
- 可能过度依赖检索质量（检索错误 → 生成错误）
- 限制了 LLM 的推理和综合能力
- 生成的内容可能不够流畅（过于贴近原文）

## 评估指标

> [!math] 核心指标
>
> **Citation Recall（引用召回率）**：
> $$\text{Recall} = \frac{\text{有引用支持的陈述数}}{\text{总陈述数}}$$
> 衡量"有多少内容被归因"。
>
> **Citation Precision（引用精确率）**：
> $$\text{Precision} = \frac{\text{引用正确的陈述数}}{\text{有引用的陈述数}}$$
> 衡量"引用是否准确"。
>
> **Support Accuracy（支持准确性）**：
> 引用的文档是否真的支持该陈述（需要人工标注或 NLI 模型判断）。

### 评估挑战

1. **粒度问题**：
   - 句子级引用 vs 段落级引用 vs 文档级引用
   - 粒度太粗 → 用户难以定位具体证据
   - 粒度太细 → 引用过多，干扰阅读

2. **支持关系的模糊性**：
   - **直接引用**：原文照搬 → 容易判断
   - **改写**：语义相同但表述不同 → 需要语义匹配
   - **推理**：结论需要多个来源综合推理 → 难以归因到单一来源

3. **幻觉的隐蔽性**：
   - LLM 可能生成"看似有引用"但实际不支持的内容
   - 示例：引用 [1] 说"Transformer 使用 RNN"，但 [1] 实际说的是相反的内容

## 在 RAG 系统中的角色

Citation Generation 是 [[RAG]] 生成阶段的**信任层**：

```
检索 (Retrieval) → 整合 (Integration) → 生成 (Generation)
                                              ↓
                                      Citation Generation
                                              ↓
                                      可验证的输出
```

**与其他组件的交互**：
- **检索质量**：引用质量的上限取决于检索到的文档是否相关
- **[[Reranking]]**：重排序可以将最相关的文档排在前面，提高引用准确性
- **[[Context Compression]]**：压缩后的上下文可能丢失细节，影响引用粒度

## 局限性

> [!warning] 边界条件
>
> **1. 引用不等于正确**：
> - 引用的文档本身可能错误或过时
> - LLM 可能误解文档内容
>
> **2. 无法归因的知识**：
> - 常识性知识（如"地球是圆的"）可能不需要引用
> - 推理性结论（综合多个来源）难以归因到单一文档
>
> **3. 引用的成本**：
> - Inline citation 需要训练数据和模型支持
> - Post-hoc attribution 增加延迟
> - 过多引用影响阅读体验
>
> **4. 对抗性攻击**：
> - LLM 可能学会"伪造引用"（生成看似合理但实际不存在的引用）
> - 需要额外的验证机制

> [!interview] 面试视角
>
> **Q: Citation Generation 和传统的参考文献有什么区别？**
> A: 传统参考文献是文档级的（整篇文章引用另一篇文章），而 Citation Generation 是**句子级或 claim 级**的——每个具体陈述都标注来源。这让读者可以精确验证每个事实，而不是笼统地说"参考了某篇论文"。
>
> **Q: 为什么不直接让 LLM 只输出检索到的原文？**
> A: 因为用户需要的是**综合和推理**，而不是原文堆砌。Citation Generation 的目标是在保持生成灵活性的同时，提供可验证性——既能改写、总结、推理，又能追溯到原始来源。
>
> **Q: 如何判断一个引用是否真的支持陈述？**
> A: 这是 **Support Accuracy** 评估的核心挑战。常用方法：
> - **人工标注**：最准确但成本高
> - **NLI 模型**：判断文档是否蕴含（entail）陈述
> - **语义相似度**：计算 embedding 距离（但可能误判改写）
>
> **Q: Post-hoc attribution 的主要挑战是什么？**
> A: **语义匹配的模糊性**。LLM 可能改写了原文（如"Transformer 使用自注意力" vs "自注意力是 Transformer 的核心"），语义相同但表述不同。简单的字符串匹配会失败，需要语义理解模型。
