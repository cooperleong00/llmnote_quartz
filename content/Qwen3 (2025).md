# Qwen3

Qwen3 是阿里巴巴 Qwen 团队发布的最新一代大语言模型系列。其核心创新在于**将 thinking mode（推理模式）和 non-thinking mode（快速响应模式）统一到单一模型中**，用户可以通过 `/think` 和 `/no_think` 标志动态切换，无需部署多个模型。旗舰模型 Qwen3-235B-A22B 在 AIME'24 达到 85.7，AIME'25 达到 81.5，展现出强大的数学推理能力。

## 核心贡献

### 1. Thinking/Non-Thinking 双模式统一

传统上，chat 模型（如 GPT-4o）和 reasoning 模型（如 QwQ-32B）是分开的。Qwen3 首次将两种模式融合：

| 模式 | 触发方式 | 特点 | 适用场景 |
|------|----------|------|----------|
| **Thinking** | `/think`（默认） | 生成 `<think>...</think>` 推理过程 | 数学、代码、复杂推理 |
| **Non-Thinking** | `/no_think` | 空 `<think></think>` 块，直接响应 | 简单问答、创意写作 |

> [!intuition] Thinking Budget
> 一个意外发现：学会双模式后，模型自然获得了处理"中间状态"的能力。当 thinking 长度达到用户设定阈值时，可以手动插入停止指令，模型会基于已有推理生成最终答案。这种能力**未经显式训练**，是 Thinking Mode Fusion 的涌现结果。

### 2. Strong-to-Weak Distillation

对于轻量级模型（0.6B-14B 和 30B-A3B），Qwen3 采用 [[On-Policy Distillation]] 而非完整的四阶段训练：

1. **Off-policy Distillation**：用教师模型的 `/think` 和 `/no_think` 输出做 response distillation
2. **On-policy Distillation**：学生模型自己采样，与教师 logits 对齐（最小化 KL divergence）

> [!comparison] Distillation vs RL
> 在 Qwen3-8B 上的对比实验显示：
> - On-policy distillation 仅需 **1/10 GPU 小时**
> - AIME'24: 74.4 (distillation) vs 67.6 (RL)
> - Pass@64 也更高，说明 distillation 扩展了模型的探索空间

### 3. 大规模多语言预训练

- **36 万亿 tokens**，覆盖 **119 种语言和方言**（Qwen2.5 仅 29 种）
- 使用 Qwen2.5-VL 从 PDF 文档提取文本，再用 Qwen2.5 精炼
- 合成数据：用 Qwen2.5-Math 和 Qwen2.5-Coder 生成教科书、QA、代码等

## 模型规格

### Dense 模型

| 模型 | Layers | Heads (Q/KV) | Context | Tie Embedding |
|------|--------|--------------|---------|---------------|
| Qwen3-0.6B | 28 | 16/8 | 32K | Yes |
| Qwen3-1.7B | 28 | 16/8 | 32K | Yes |
| Qwen3-4B | 36 | 32/8 | 128K | Yes |
| Qwen3-8B | 36 | 32/8 | 128K | No |
| Qwen3-14B | 40 | 40/8 | 128K | No |
| Qwen3-32B | 64 | 64/8 | 128K | No |

### MoE 模型

| 模型 | Layers | Heads (Q/KV) | Experts (Total/Activated) | Context |
|------|--------|--------------|---------------------------|---------|
| Qwen3-30B-A3B | 48 | 32/4 | 128/8 | 128K |
| Qwen3-235B-A22B | 94 | 64/4 | 128/8 | 128K |

### 架构特点

- 基于 Qwen2.5 架构：[[Grouped-Query Attention|GQA]]、SwiGLU、[[RoPE]]、RMSNorm
- **移除 QKV-bias**，引入 **QK-Norm** 确保训练稳定性
- MoE 采用 fine-grained expert segmentation（128 专家，每 token 激活 8 个）
- **无共享专家**（与 Qwen2.5-MoE 不同）
- 使用 **global-batch load balancing loss** 促进专家专业化

## 训练流程

### Pre-training（三阶段）

```
Stage 1: General (30T tokens, 4K context)
    ↓ 语言能力 + 世界知识
Stage 2: Reasoning (5T tokens, 4K context)
    ↓ 增加 STEM/代码/推理数据比例
Stage 3: Long Context (100B+ tokens, 32K context)
    ↓ RoPE base 10K→1M，YARN + DCA 实现 4x 推理扩展
```

### Post-training（四阶段）

```
Stage 1: Long-CoT Cold Start
    ↓ 用 QwQ-32B 生成推理数据，严格过滤
Stage 2: Reasoning RL
    ↓ GRPO，3995 query-verifier pairs
    ↓ AIME'24: 70.1 → 85.1 (170 steps)
Stage 3: Thinking Mode Fusion
    ↓ 融合 thinking + non-thinking 数据
    ↓ 设计 /think 和 /no_think chat template
Stage 4: General RL
    ↓ 20+ 任务的 reward system
    ↓ 提升 instruction following、agent 能力
```

> [!warning] 性能权衡
> Thinking Mode Fusion 和 General RL 会略微降低 thinking mode 在 AIME/LiveCodeBench 上的表现（约 1-2 分），但显著提升通用能力和模式切换准确性（ThinkFollow: 88.7 → 98.9）。

## 性能表现

### Thinking Mode（旗舰模型 235B-A22B）

| Benchmark | Score | 对比 |
|-----------|-------|------|
| AIME'24 | 85.7 | 竞争 o1, o3-mini |
| AIME'25 | 81.5 | - |
| LiveCodeBench v5 | 70.7 | - |
| CodeForces | 2,056 | - |
| BFCL v3 | 70.8 | Agent 任务 |

### Thinking Budget 效果

实验表明，增加 thinking budget 可以持续提升性能，且曲线平滑。32K 以上的 budget 预期还能进一步提升。

## 技术亮点

### Reasoning RL 的关键发现

- **大 batch size + 高 rollout 数量** 有益
- **Off-policy training** 提升样本效率
- 通过控制 **entropy** 平衡 exploration/exploitation
- 单次 RL run 即可稳定提升，无需手动调参

### General RL 的 Reward 设计

| Reward 类型 | 用途 | 特点 |
|-------------|------|------|
| Rule-based | Instruction following, format | 高精度，防 reward hacking |
| Model-based (有参考答案) | 多样任务 | 灵活，避免 false negative |
| Model-based (无参考答案) | 开放式问题 | 基于 preference data 训练 |

## 局限性

1. **Thinking mode 在通用训练后略有下降**：为了提升整体 versatility 接受的权衡
2. **长 thinking 的效率**：32K+ 的 thinking budget 尚未充分探索
3. **多语言质量不均**：119 种语言中低资源语言的质量仍有提升空间

## 面试要点

> [!interview] Q: Qwen3 的 thinking mode 和 non-thinking mode 是怎么实现的？
> A: 通过 chat template 设计。用户在 query 中加 `/think` 或 `/no_think` 标志，模型根据标志决定是否生成 `<think>` 块。Non-thinking mode 保留空的 `<think></think>` 块以保持格式一致性。这种设计允许开发者通过预填充空 think 块来强制禁用 thinking。

> [!interview] Q: 为什么 Qwen3 用 distillation 而不是 RL 训练小模型？
> A: 实验表明 on-policy distillation 比 RL 高效 10 倍，且性能更好。关键原因是 distillation 从教师 logits 学习，能扩展学生的探索空间（更高的 pass@64），而 RL 只能从自身采样学习。

> [!interview] Q: Qwen3 的 MoE 设计和 Qwen2.5-MoE 有什么区别？
> A: 主要区别是**移除了共享专家**，并采用 **global-batch load balancing loss** 替代传统的 auxiliary loss。这促进了专家专业化，提升了下游任务性能。
